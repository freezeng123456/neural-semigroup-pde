# 官方 DUE VorticityOSG 两臂结果独立审阅

审阅日期：2026-10-04。范围：两臂验收 JSON、训练与 checkpoint 回执、配对比较脚本及其已生成指标。未重新计算完整预测数组，未运行推理或训练，未修改回收证据、源代码或其他报告。

## 1. 可以得出的结论

**官方 DUE 的完整基线已跑通。在同一个 FNO 架构、相同初始参数、seed 0 和各 500 轮训练下，默认 GDSG 在这 100 条公开测试轨迹上的长程预测明显优于作者支持的 SG0 普通拟合分支。** 末步平均相对 L2 误差从 2.84100962 降至 0.0173916649；逐轨迹比较，100/100 条的末步误差更低。

这说明当前骨干已经能够在作者训练流程下取得约 **1.74% 的末步平均误差**。现有证据不支持将 SG0 的失败直接解释为“参数量太少，必须先扩容”。同时，这一比较还不足以证明更大网络没有收益、某个训练干预单独造成了改进，或 GDSG 在其他训练种子上必然取得同样结果。

主指标统一采用验收文件中的 **`author_float32`**，时间轴为距公开测试首帧的 **elapsed 0…99**。首帧绝对时刻未知。完整指标见 [metrics.json](metrics.json)。

## 2. 数值比较及其含义

表中误差均为无量纲比值；例如 `0.01739` 对应约 `1.739%`。

| 同一测试指标 | SG0 | GDSG |
|---|---:|---:|
| elapsed 1，平均相对 L2 | 0.00130279153 | 0.00154337776 |
| elapsed 20，平均相对 L2 | 0.00551730208 | 0.00612583617 |
| elapsed 40，平均相对 L2 | 0.0245493166 | 0.00847692415 |
| elapsed 60，平均相对 L2 | 0.222436443 | 0.0105108703 |
| elapsed 99，平均相对 L2 | **2.84100962** | **0.0173916649** |
| elapsed 99，中位数 | 0.994238228 | 0.0117913680 |
| elapsed 99，10%–90% 分位数 | 0.651742065–4.91551285 | 0.00820758734–0.0317618407 |
| elapsed 99，最大值 | 42.8416901 | 0.103839576 |
| 作者 stdout 的逐轨迹时空联合误差均值 | 0.702999294 | 0.0106825354 |

末步均值的 SG0/GDSG 比为约 **163.35**，相对下降 **99.3878%**。这两个数是“两个均值的比及其下降比例”，不是逐轨迹改进倍数的平均。时空联合指标的 SG0/GDSG 比约为 **65.81**；其定义是先对每条轨迹合并全部空间和时间取范数比，再对轨迹取平均，不能当作末步误差。

配对统计也支持改进不只是由少数 SG0 异常轨迹驱动：末步和时空联合指标均为 GDSG **100 胜、0 平、0 负**。末步配对差 `GDSG−SG0` 的均值为 `−2.8236172034`、中位数为 `−0.9814728801`。配对计算使用保存的 float32 误差转 float64 后相减，方向与索引正确，未混用另一种精度口径。[逐轨迹配对 CSV](paired_trajectory_errors.csv)

**GDSG 并没有在所有预测时刻都更好。** elapsed 1…23 的平均误差均高于 SG0；第 1 步仅 9/100 条轨迹更好、91/100 更差。平均曲线从 elapsed 24 开始低于 SG0，但当时逐轨迹仍只有 40/100 更好。到 elapsed 60 和 99，才在列出的这些时刻均达到 100/100 更好。均值曲线交叉与多数轨迹转优是不同事实。[完整时间曲线及逐时配对统计](test_curves_and_paired_changes.csv)

所以，本次结果最直接支持的是长程误差增长受到抑制。不能将它写成“GDSG 普遍降低一步拟合误差”，也不能把有限窗口内的良好预测提升为全局动力学稳定性定理。

- 对比脚本读取已经通过验收的指标，检查原输入哈希并采用同测试轨迹索引配对。本次复核其符号、精度、时间轴、配置门槛和成本字段，未发现影响本次结论的错误；比较目录中的脚本、指标 JSON 与两个 CSV 的 manifest 哈希均匹配。

可以称为**官方公开代码及数据上的完整运行复现**。[DUE §5.6](https://arxiv.org/html/2504.10373v1#S5.SS6) 给出的 500 轮、batch 20、GDSG 参数 `λ=Q=1` 与当前默认臂相符。SG0 使用作者实现已有的普通拟合分支。

从现象上看，普通拟合后期误差大幅增长、GDSG 保持较低误差，与 [Deep-OSG §5.2.5](https://arxiv.org/html/2302.03358v2#S5.SS2.SSS5) 的定性结论一致。但不能声称精确复现该论文所有数值：Deep-OSG 的该案例采用最多 1,000 轮及 `λ=0.5`，与当前 DUE 默认配置不同；本地 MAT 只有 99 个单位推进间隔，且未确认绝对起时。不能用本次 elapsed 99 的 1.74% 直接宣布复现其物理 `t=100` 的数值或图线。

## 4. 公平性：相同之处与仍混合的干预

### 模型容量相同

两臂均为 modes 12×12、width 20、depth 4 的官方 OSG-FNO：作者计数为 **467,661 个可训练张量元素**，其中 **460,800 个是复数元素**；按实标量分量计为 **928,461**。这些是名义参数计数，不等于独立有效函数自由度。当前比较与早先 Burgers 的 33/1,313 参数模型无关。

相同模型类在 GDSG 下获得较好结果，表明这次 SG0 失败并非只能靠增加参数解决。它仍不能判定容量与训练的交互作用、最优容量或跨数据分布的容量需求。

### 初始化相同，不是完全配对的优化轨迹

作者模型先设置 Torch seed，再构造数据加载器；GDSG 额外生成随机状态及两段时间，SG0 不消耗这些随机数，而加载器都使用 `shuffle=True`。因此，相同 seed 和初始参数不保证相同 minibatch 顺序，不能把批顺序当作已控制变量。本次保留作者流程，没有额外重置 RNG 强行配对。[基础初始化与加载器](https://github.com/AI4Equations/due/blob/1e629104a12a9c3e3064996cbd4e301cec641ad8/due/models/pde.py#L55-L72)、[GDSG 随机抽样及加载器](https://github.com/AI4Equations/due/blob/1e629104a12a9c3e3064996cbd4e301cec641ad8/due/models/pde_osg.py#L38-L61)

### 训练 loss 不能横向比较

SG0 优化 `L_fit`；默认 GDSG 优化 `(L_fit+R)/2`，其中 `R` 是两种次序组合与直接推进之间的平均相对误差。这里既增加了组成项，也改变了监督项权重及整体缩放。它不是在保持原目标其余部分完全不变时简单附加一个惩罚。[作者两条训练分支](https://github.com/AI4Equations/due/blob/1e629104a12a9c3e3064996cbd4e301cec641ad8/due/models/pde_osg.py#L79-L118)

因此，最终训练目标 `0.0007373422` 与 `0.0004500995` 不能用来判断谁的监督训练拟合更好。两种目标都还受到每批参数更新的影响，日志也不是同一个冻结模型遍历整个训练集的统一评分。当前差异可归于**作者默认训练分支的整体干预**，尚未把组合约束、目标缩放、随机数消耗和额外计算的效应分离。

## 5. 相同更新次数，不同训练成本

| 成本项 | SG0 | GDSG |
|---|---:|---:|
| optimizer updates | 62,500 | 62,500 |
| 每 batch 的模型 forward 调用数 | 1 | 6 |
| 推导出的训练 batch forward 总调用数 | 62,500 | 375,000 |
| 实测训练时间 | 847.869 s（14.13 min） | 4,573.008 s（76.22 min） |
| Slurm elapsed | 873 s（14 min 33 s） | 4,607 s（76 min 47 s） |
| 分配 GPU 时间 | 0.2425 GPU·h | 1.27972 GPU·h |

forward 数由已观察到的更新次数与作者分支推导，未独立逐调用计数；这里指 batch 级网络调用，不是样本数或反向传播次数。两臂各用一张 Tesla V100-SXM2-32GB。实测训练时间比为 **5.394**，Slurm 时间比为 **5.277**；它们包含本次机器与运行环境的影响，不能当作普遍速度常数。GPU·h 是分配资源时长，不代表利用率或费用，表中不含预检、排队、回收与本地审计。

这次比较控制了训练轮数及更新次数，没有控制总算力。不能据此声称 GDSG 在相同 GPU 时间下最优。两臂预测时使用同一网络结构，GDSG 的训练额外调用也不自动变成预测额外调用。

## 6. checkpoint、收敛与统计边界

**主结果使用最终第 500 轮模型。** 这是原作者入口训练后直接调用内存中网络预测的行为；没有根据测试曲线换成别的 checkpoint。两臂“训练目标最小”的保存轮次都恰好也是 500，由未舍入的 epoch event 数值确定。它是训练目标最优轮次，不是独立验证或测试最优轮次。[原入口第 13–17 行](https://github.com/AI4Equations/due/blob/1e629104a12a9c3e3064996cbd4e301cec641ad8/examples/VorticityOSG/VorticityOSG.py#L13-L17)

训练日志末段趋缓不能证明充分收敛：cosine 学习率在第 500 轮降到 0，而且此流程没有独立验证集。当前结果也不能预测给 SG0 更多更新或同等计算预算后的表现。

每臂只有 **一个训练种子**。100 条配对测试轨迹刻画的是这两个已训练模型在该测试集上的差异，不是 100 次独立重训练。100/100 胜出是有用的描述性结果，不能据此报告跨训练种子的显著性、胜率置信区间或稳定排名。图中的 10%–90% 区间是轨迹分布范围，不是置信区间。

这两臂配置在完整结果出现前已经固定，当前比较仍可清楚报告。但我们已经检查这 100 条测试轨迹并据此诊断、讨论新方法，它们后续应视为探索性基准；不得边看同一测试集边选模型后再称最终独立泛化验证。

**用于后续工作的简短结论：** 基线已完成，现有 FNO 容量能够支持良好长程预测；下一步应以已验证的 GDSG 最终模型作为强基线，保留同一指标、时间轴与成本口径。当前证据还没有证明我们自己的方法、某种扩容策略或新的稳定性机制优于它。
