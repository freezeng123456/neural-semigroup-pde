# DUE VorticityOSG 原始数据生成来源核查

核查日期：2026-10-04。范围：公开论文、作者主页、公开 GitHub 文件树和已验收 MAT 清单。未运行模拟器、模型推理或训练，未修改冻结 DUE 源码。

## 1. 结论

**目前未找到能够归档并直接复用的 DUE / Deep-OSG 原作者 Navier–Stokes 数据生成代码。** 已确认论文给出的方程、初态分布描述和训练数据截取方法；原始数值求解器、内部步长、去混叠规则、随机种子及测试首帧的绝对时刻仍缺证据。

因此，现在可以准确复用已下载的作者测试轨迹开展描述性诊断；还不能声称能够重建其原始数据分布，生成“与原测试集同分布”的新确认轨迹，或得到扰动状态下已验证的参考一步流映射。公开文献足以支持另行建立一个数值参考问题，但它需要单独的来源、离散约定和精度验证，不能冒称原作者生成器。

“未找到”限于下述已查范围，不等于证明作者没有保存代码或没有其他公开位置。

## 2. 可核查来源链

1. **DUE 明确使用 Deep-OSG 数据。** [DUE v1 §5.6](https://arxiv.org/html/2504.10373v1#S5.SS6) 将涡度数据来源指向参考文献 [9]，即 Chen–Wu 的 Deep-OSG；同时描述 100 条训练轨迹、64×64 采样网格、随机时滞 [0.5,1.5]。
2. **作者仓库提供成品 MAT。** 冻结 [README 第 41–43 行](https://github.com/AI4Equations/due/blob/1e629104a12a9c3e3064996cbd4e301cec641ad8/README.md#L41-L43) 指向公开数据文件夹。实际 [VorticityOSG.py 第 4–17 行](https://github.com/AI4Equations/due/blob/1e629104a12a9c3e3064996cbd4e301cec641ad8/examples/VorticityOSG/VorticityOSG.py#L4-L17) 只负责读取两个 MAT、训练和预测，没有调用参考 PDE 求解器。
3. **公开目录检索没有补上生成代码。** 已核查 `main` commit `1e629104a12a9c3e3064996cbd4e301cec641ad8` 的全部 75 个文件，以及旧 `master` commit `da79d4875841bb2a5132a830071459195a2190e2` 的全部 49 个文件；两份 API 文件树均 `truncated=false`。旧分支存在其他方程的生成文件，但 VorticityOSG 对应目录仍仅有入口、网络和配置。[main 完整树](https://api.github.com/repos/AI4Equations/due/git/trees/1e629104a12a9c3e3064996cbd4e301cec641ad8?recursive=1)、[master 完整树](https://api.github.com/repos/AI4Equations/due/git/trees/da79d4875841bb2a5132a830071459195a2190e2?recursive=1)。
4. **作者主页没有给 Deep-OSG 专用代码链接。** [Chen 的论文列表](https://junfeng-chen.github.io/publications.html) 中，Deep-OSG 条目只有 Paper 链接；DUE 和 PiT 条目另有 Code 链接。也检查了 [Chen 公开仓库列表](https://api.github.com/users/junfeng-chen/repos?per_page=100)、[AI4Equations 公开仓库列表](https://api.github.com/users/AI4Equations/repos?per_page=100) 和 [Wu 的主页](https://sites.google.com/site/klwuhomepage/)，没有定位到 Deep-OSG 涡度生成器。PiT 的公开文件树也未见该生成器；不能把另一个任务的训练入口当作数据来源。

上述 API 响应和作者论文列表已保存至 retrieval_receipt.json（历史文件路径；原始产物已按保留策略舍弃），附原 URL、查询时间、字节数及 SHA-256。未遍历全部历史提交；没有据此作“历史上从未公开”的断言。

## 3. 哪些生成条件已经确定

[Deep-OSG v2 §5.2.5](https://arxiv.org/html/2302.03358v2#S5.SS2.SSS5) 给出：

\[
\partial_t\omega+v\cdot\nabla\omega=10^{-3}\Delta\omega+f,
\qquad \nabla\cdot v=0,
\]
\[
f(x,y)=0.1\{\sin[2\pi(x+y)]+\cos[2\pi(x+y)]\},\quad (x,y)\in(0,1)^2.
\]

文中采用周期条件、64×64 网格；100 个初始场来自
\[
\mu=\mathcal N\!\left(0,7^3(-\Delta+49I)^{-2.5}\right).
\]
每条采集 110 个随机时滞快照，保留最后 51 帧作为训练数据，以减弱高斯初始化的影响。这里有明确的早期演化截取，不能把保存的训练首帧视作新抽取的高斯场。文中没有给出对应的数值生成代码、内部步长、训练截取前的累计时间或测试首帧绝对时刻。

以下以“已经确认”与“仍需来源”分列，避免将合理猜测写成协议。

| 项目 | 当前证据 | 尚缺内容 |
|---|---|---|
| 方程、黏度、外力 | 两篇论文相符；上式 | 数值实现中的符号、轴向和速度恢复约定 |
| 空间网格 | Deep-OSG 说明 64×64 生成；MAT 坐标为 0 到 63/64 | 是否另有内部高分辨率计算、滤波或截取步骤的代码证明 |
| FFT / 空间离散 | DUE 网络使用 FFT，但那是学习器 | 参考求解器是否采用伪谱法；FFT 归一化、波数排列和 Nyquist 处理 |
| 非线性去混叠 | Deep-OSG 的 NS 段落未说明 | 2/3 截断、3/2 扩展或其他规则；掩码位置 |
| 内部时间积分 | 保存数据有随机观测时滞 | 内部积分方法、步长、误差控制；是否准确落在随机观测时刻 |
| 初态抽样 | 论文给出周期高斯协方差 | 离散采样器、幅度归一化、零模处理和随机种子 |
| 训练起时 | 保留早期演化后的末 51 帧 | 110 的具体索引约定、被丢弃时滞及每条绝对起时 |
| 测试起时 | 公开文件含 100 状态及 99 个单位时滞 | 是否也预演化、预演化多久、首帧是物理哪个时刻 |

## 4. 为什么不能直接继承 FNO 的生成配置

Deep-OSG 的初态描述引用原 FNO 论文，但这不构成两套生成程序完全相同的证据。[FNO v3 附录 A.3.3](https://arxiv.org/html/2010.08895v3#A1.SS3.SSS3) 确实描述流函数伪谱求解、傅里叶空间 Poisson 求解、物理空间非线性计算及去混叠；时间推进采用非线性显式处理的 Crank–Nicolson 更新，内部步长 `1e-4`，256×256 生成后降采样到 64×64，每 1 个时间单位记录。

这与 Deep-OSG 的 64×64 生成、随机观测时滞描述并不相同。此外，FNO 附录写出的协方差前因子是 `7^(3/2)`，Deep-OSG 写的是 `7^3`；[FNO PDF 第 15 页](https://arxiv.org/pdf/2010.08895v3#page=15) 也有前一种写法。缺少实际采样代码时，不能判断这是文字约定、排印问题还是实现差异。

所以，`dt=1e-4`、Crank–Nicolson、256² 降采样，以及某一种去混叠掩码，都只能作为 FNO 的公开方法信息。它们目前不是 DUE MAT 的已证实元数据。本次没有下载其他人的同类求解器作为替代，也没有实现或运行新的生成器。

## 5. 成品 MAT 能证明什么

以已完成的 [数据清单](data/manifest.json) 为准：

| 文件 | 状态形状 | 时滞 | 本地 SHA-256 |
|---|---|---|---|
| `VorticityOSG_train.mat` | `(100,64,64,1,51)` | `(100,50)`，范围 0.5006624505–1.4997749156 | `0ebdd969d52292b4304d3583b3cd432c288397b367f75372d06944d629c5d111` |
| `VorticityOSG_test.mat` | `(100,64,64,1,100)` | `(100,99)`，全为 1 | `a1e0a3a0fdf63c1ec3622bc21bd7889bf4a14078f86d63e07d8ae2bab74d926a` |

训练文件只有 `coordinates`、`dt`、`trajectories`；测试文件只有后两项。没有生成种子、求解器配置或绝对时间数组。MAT 头中的 2024-01-15 是文件生成时间，不是 PDE 的起始时刻。文件存为 MATLAB double 也不能证明内部积分使用了 float64。

当前主评测应继续称“距公开测试首帧的 elapsed 0…99”，不能仅凭论文图注把最后一帧改称物理 `t=100`。SHA-256 确保我们后续使用同一份文件，不能反推出原始生成算法。

## 6. 对新确认数据和扰动真值的含义

**未查看的新确认轨迹：** 要宣称与作者分布一致，至少还需原生成器及配置，尤其是离散初态抽样、预演化和测试取帧方法。已经查看的 100 条测试轨迹不能再次充当新方法选定后的独立确认集；在现有轨迹中换时刻或添加扰动，也不产生新的独立轨迹。

**扰动状态的一步参考：** 已知连续方程还不足以确认 64² 上哪个离散流映射生成了 MAT。应先明确速度的常量分量、涡度零模、网格到连续场的解释和高频处理。周期速度的旋度应有零空间均值；对带有明显均值偏置的模型输出，直接推进或先去均值是两个不同的问题，不能悄悄替换。

即使取得原代码，也仍需在现有真实状态上核验一步重启，并检查时间步、空间分辨率加密误差；对有较强高频成分的扰动输入还需单独验证。旧轨迹上的重现用于参考程序校验，新方法的模型选择仍需与确认数据分开。

当前可执行判断是：**原作者生成器来源尚未闭合，暂不将任何新增数值推进标注为“DUE 原始真值”。** 若后续选择自行建立参考求解器，应先明确它是一个另行验证的同方程参考基准，再决定能支持何种比较。本次没有联系作者、提交作业或生成新数据。
